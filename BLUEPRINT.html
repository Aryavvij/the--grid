// The 6 things that make this genuinely different
⌘ The 60-Second Day
One glass overlay batches the entire day: pre-checked auto-resolved items, one-tap binaries, steppers, scales. One SEAL DAY commit. No per-page navigation, ever.
▦ Data That Logs Itself
DERIVED metrics complete with zero input — "Trained" from GymLog, "Deep work 90m" from Focus sessions, "Rent paid" from the recurring engine. Half the console is pre-filled before you open it.
◎ Focus Engine
A full-bleed deep-work view with contexts (courses/projects), 50/10 blocks, distraction capture inbox, and auto-completion of study metrics. Students never "log studying" again.
▮ Anti-Fragile Streaks
Partial credit counts (score ≥ 0.5). Rest days never break chains. Every 7 perfect days banks a Repair Token that patches a miss — rendered as a hollow ring, visibly repaired, never faked.
✨ Ignition UX
A 600ms completion sequence — scale snap, emerald wipe, ring pulse, streak digit roll — and a scarce neon column sweep reserved for 100% days. Addictive, never clownish.
⬢ One Truth Source
The demo/localStorage fork dies. One API client + offline queue. Versioned metric definitions mean you can edit any target without corrupting a single day of history.
// Design DNA — the Carbon-Green rules everything obeys
Matte Carbon Surfaces
5-step gray scale #0A0C0B → #262C29, never pure black. Carbon-fiber weave texture on hero panels only. Glass reserved for overlays — glass-on-glass is how premium dies.
Green Is Information
One hue, five intensities (#1A3326 → #39FF8E). Cell color = completion score. Neon #39FF8E on max 2 elements per viewport: streak fire and live counters only.
Mono Numerals
Every number in JetBrains Mono with tabular-nums, right-aligned. Inter for interface, Space Grotesk for display. Uppercase mono labels with .08em tracking — already the brand, kept.

A1
Typed Metric Engine
5 metric types · completion functions · 0–1 score drives grid color · kills F2
🔥 Core upgradeNEW

Replace completed: Boolean with typed metrics. Each type has a completion function normalizing every log to a 0–1.25 score — the single number that colors the heat-wall, feeds streaks, and powers the day composite.

TypeInputCompletion fnExample
BINARYone tap1 | 0"Made bed"
QUANTITYnumber + unit (stepper)min(value/target, 1.25)"3L water", "40 pages"
DURATIONminutes — manual or auto from Focus Enginemin(value/target, 1.25)"90 min deep work"
SCALE1–5 single tapvalue / 5"Energy", "Sleep quality"
DERIVEDnone — computed from other modulesmodule-specific"Trained" ← GymLog · "Under budget" ← Transactions
⬡ CRUD contract
C — POST /metrics creates def + version v1 (name, type, target, unit, schedule, derivedSource?)
R — GET /metrics/matrix?from&to one call: defs + logs + server-cached streaks/scores
U — PATCH /metrics/:id writes a new version row (effectiveFrom) — history never mutates
D — soft-archive only; logs persist, greyed in history, absent from today
◉ Rules
Score capped at 1.25 — overshoot renders as a #39FF8E shimmer without breaking the scale
Cell color bands: score → signal-100 / 300 / 500 / 700 / 900
Migration is lossless: Habit→MetricDef(BINARY), HabitLog→MetricLog(value:1) in one Prisma migration
MetricDefMetricVersionMetricLogscore: Float 0–1.25source: MANUAL|DERIVED|REPAIR

✦ The readiness mechanic
Readiness = sleep × recovery × yesterday's load. It renders as the panel's border intensity — signal-100 (deload) to signal-700 (push). The panel itself tells you what kind of day it is, with zero extra UI.
A5
Streak 2.0 — Anti-Fragile Chains
partial credit · scheduled-days-only · Repair Tokens · kills F3
NEWRetention-critical
◈ The rules
Streak = consecutive scheduled days with score ≥ 0.5 — partial credit counts
Rest days defined in targetDays never break chains
Every 7 perfect days banks 1 Repair Token (max 2)
A token auto-fills a missed day at score 0.5, source REPAIR
◉ Honest rendering
Repaired days render as a hollow ring — visibly repaired, never faked
Unlogged past days are --carbon-3 with a dot — neutral, recoverable, shame-free. Never red.
Milestones at 7/30/100: neon chip, double glow pulse, mono toast STREAK_07 // SYSTEM NOMINAL
A6
DayAggregate Cache + Offline Queue
server-side composite scores · IndexedDB replay · kills F5 + F6
NEW INFRA
◈ DayAggregate
One row per (userId, date): compositeScore, sealed flag, streakCount
Written by the server inside every /days/:date/commit transaction
Heat-wall reads 365 aggregate rows — not thousands of logs. F6 dead.
◈ Offline queue
Failed commits land in IndexedDB with a monotonic sequence
Replay on reconnect; server upserts are idempotent via (defId, loggedDate) uniqueness
This is what makes deleting the localStorage fork safe (DELETE-04)

✕ Cuts — every deletion is a feature for the user's attention

Logging fatigue is death by a thousand inputs. Each cut below names the mechanism of harm and the exact replacement. Nothing is deleted without something cheaper absorbing its job.

D1
Manual "studied / worked" habits
redundant the moment the Focus Engine exists
DELETE INPUT
Harm: double entry — you did the work in a timer, then you log the work again. Every duplicate input erodes trust in the whole system.
Replacement: DERIVED metrics auto-complete from FocusSession rows. The metric stays on the grid; only the input disappears.
D2
Per-transaction finance entry as the default
the #1 documented finance-tracker killer
DELETE DEFAULT
Harm: nobody itemizes every coffee past week 3; once entries lapse, the budget view becomes fiction and the user abandons the module entirely.
Replacement: U4 — recurring engine auto-posts fixed costs; only variable spend is logged (2 taps, in-console); full transaction entry remains available but demoted to power-user path.
D3
Mood / journal / gratitude prompts
guilt generators masquerading as wellness
NEVER ADD
Harm: open-text prompts create a nightly homework assignment; skipping them produces visible blanks that read as failure.
Replacement: one optional end-of-day SCALE tap ("Energy ①–⑤"). Skippable with zero visual penalty. Never nagging, no notifications.
D4
The demo/localStorage storage fork
14+ duplicated keys · wipe-on-switch · 2× implementation tax
DELETETop bug factory
Harm: two truth sources; the last five commits are all persistence/sync firefighting; demo users lose all data at signup.
Replacement: one API client everywhere + the A6 offline queue. "Demo" becomes a server-seeded sandbox account; signup claims the account and keeps the data. One code path, forever.
D5
Per-module navigation for daily logging
5+ page visits to update one day
DELETE PATH
Harm: friction F1 — ~4–6 minutes of navigation per day purely to record what already happened.
Replacement: the Daily Console (A2). Module pages survive for deep dives and editing; they just stop being the logging path.
D6
Resume builder's permanent dock slot
quarterly tool in a daily loop
DEMOTE
Harm: prime navigation real estate spent on a tool touched four times a year.
Replacement: feature moves intact to a utility drawer (with settings/export). Its dock slot goes to FOCUS — a daily-use surface.
D7
Streak-zeroing & red "missed" days
punishes the user for living
DELETE MECHANIC
Harm: a single sick day wipes 40 days of accumulated identity. The day after a broken streak is the highest-churn moment in any tracker.
Replacement: Streak 2.0 (A5) — partial credit, scheduled-days-only, Repair Tokens rendered as hollow rings. Missed days render neutral carbon, never red.

✕ The dogma
Every habit tracker ever built shows all N habits at equal weight — a wall of checkboxes.
Anki does the opposite: it never shows you 5,000 cards, only the ones about to be forgotten.
Grid currently shows 12 nodes with identical visual priority. The user must do the triage the system should do.
◉ The mechanic
fragility = (1 − recentCompletionRate) × streakValueAtStake × daysSinceLastLog
Surface the single node most likely to break today, not the wall.

Computes entirely from data DayAggregate + MetricLog already produce. Near-zero marginal cost.
✦ Why it matters

✦ ECharts over Bklit UI (constraint-forced, 2026.07.23)

External signals flow in through one secured ingest spine, not bespoke code per source. Every integration reuses the shipped security layer (validate() + rate limiter + API key). Three connectors planned: GitHub → Projects, Fitbit → Vitals, GPay → Finances.
